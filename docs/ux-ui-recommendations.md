# UX/UI-рекомендации для Irbis

Документ фиксирует анализ компоновки и форм (не цветовой темы) и практичный roadmap
после закрытия базового функционала (в т.ч. настройка через РКЧХ).

**Контекст.** Irbis — desktop Qt 6: идентификация, анализ ПФ, синтез регулятора,
графики откликов. Математика — numina; UI — вкладки + собственные виджеты (`TranFuncForm`,
графики, метрики).

**Сильная сторона продукта.** Богатый сквозной функционал «в одном месте», который редко
собирают целиком. Цель UI — не «выглядеть модно», а дать **ясную иерархию** и приятный
ритм работы инженера.

---

## 1. Что уже хорошо

1. **Ментальная модель вкладок** — идентификация → анализ → синтез → (РИМ/РКЧХ).
2. **Графики как центр** — норма для научного/инженерного desktop (MATLAB, LabVIEW, CST).
3. **Повторяемый паттерн** вкладок: модель сверху, действия, графики снизу — узнаваемость.
4. **Отдельное окно просмотра графика** — детальная работа ≠ мини-превью на вкладке.

Проблема обычно не в «отсутствии идей», а в том, что **всё одинаково важно** и **верхняя
зона перегружена**.

---

## 2. Главная проблема: нет «сцены»

Типичная текущая схема:

```
[ПФ-редактор ........ метрики]
[кнопки ........................]
[графики ........................]
```

Приятнее, когда есть **три зоны с разным весом**:

| Зона | Роль | Пример |
|------|------|--------|
| **A. Объект** | «С чем работаю» | W(p), тип звена, τ |
| **B. Действия** | «Что сделать» | добавить / заменить / параметры |
| **C. Результат** | «Что получилось» | графики + метрики |

Сейчас **метрики** часто стоят рядом с ПФ, а **графики** — отдельно внизу. Метрики
логичнее рядом с **результатом** (колонка у графиков или блок над/под ними), а не в одном
ряду с формулой.

**Рекомендация.**

- Слева/сверху: компактный блок **«Модель»** (ПФ).
- Справа от графиков или под ними: **«Качество»** (метрики).
- Одна **полоса действий** между моделью и графиками.

Чтение сверху вниз: *модель → действие → отклик*.

## 3. Форма передаточной функции (ПФ)

Текущий `TranFuncForm` — «печатная» дробь с полем на каждую степень:

```
W(p) =  [a0][a1]…[a5]
        ─────────────  · e^{−τp}
        [b0][b1]…[b5]
```

### 3.1. Почему форма часто «некрасива» и тяжела

1. **Слишком много пустых степеней**  
   Порядок до 6 всегда на экране → много «+0» и неактивных `p^k`. Выглядит как таблица,
   а не как формула.

2. **Смешаны два режима**  
   - *Чтение*: «как в учебнике».  
   - *Редактирование*: «как в Excel».  
   Одновременно хорошо почти нигде не получается. В MATLAB чаще `tf(num, den)` или
   специализированный tuner, а не 12 полей сразу.

3. **Overlay-кнопки** (copy/paste)  
   «Плавающие» кнопки чуть ломают геометрию и ощущение законченности блока.

4. **Визуальный вес**  
   Крупный `W(p) =` + коэффициенты + `e` забирают внимание у графиков, хотя графики —
   главный результат.

### 3.2. Предложения (по приоритету)

#### A. Режим «формула + компактный редактор» (лучший баланс)

- **По умолчанию** — красивая read-only формула (в духе `TfDisplayWidget` / HTML):  
  `W(p) = (2p+1)/(p²+3p+2) · e^{−0.5p}`
- **Редактирование** — по клику или кнопке «Изменить»:
  - числитель / знаменатель **одной строкой** (`1 3 2` или `p^2+3p+2`);
  - **порядок** (n, m) spinbox;
  - **τ** отдельно.
- Поля по степеням — **опционально** («Расширенный вид»).

Сохраняется математическая эстетика, убирается «таблица нулей».

#### B. Если оставлять поля по степеням

- Показывать только **активные** степени (до max ненулевого + 1 запас).
- Кнопки **+степень / −степень** вместо всегда 6×6.
- Числитель и знаменатель **выровнять** (high→low или low→high — единообразно).
- «Мёртвые» `p^k` не рисовать, а не только серить.

#### C. Запаздывание

- Не всегда `e^{−τp}` в одной линии с дробью.
- Чекбокс **«Запаздывание»** + поле τ **под** формулой:  
  `☐ Запаздывание τ = [ 0.50 ] с`  
  Меньше шума при τ = 0.

#### D. Copy / paste

- В **тулбар блока «Модель»** или в контекстное меню по формуле — не overlay.

#### E. Имя звена («апериодическое» …)

- Сейчас часто рядом с кнопками. Лучше **подпись под формулой** secondary-текстом:  
  `Тип: инерционное 1-го порядка`  
  Кнопки — только действия.

## 4. Экраны и ритм вкладок

### 4.1. Единый каркас вкладки

Один layout-шаблон для Анализ / Синтез / Идентификация:

```
┌─ Заголовок вкладки (1 строка) ─────────────────────┐
│  «Анализ» · краткая подсказка                        │
├─ Карточка «Модель» ──────────┬─ (опц. параметры) ───┤
│  ПФ / результат идентификации│  регулятор (синтез)  │
├─ Панель действий (одна линия) ──────────────────────┤
│  [графики] [параметры] [+] [↻] [×]   статус: …      │
├─ Результат ─────────────────────────────────────────┤
│  ┌─ графики (stretch) ──────────┬─ метрики ─┐       │
│  │                              │  tр  …    │       │
│  └──────────────────────────────┴───────────┘       │
└─────────────────────────────────────────────────────┘
```

**Карточки** (`QFrame` + лёгкая рамка/фон, padding 12–16 px) успокаивают Qt-UI: глаз видит
блоки, а не россыпь виджетов.

### 4.2. Кнопки-иконки

Сейчас: ряд 40×40. Минусы — нужны tooltips, неочевидно главное действие.

Рекомендации:

- **Primary** — с текстом: `Добавить`, `Идентифицировать`, `Автосинтез`.
- Вторичные — иконки.
- Группировка с визуальным разделением:  
  `[Параметры] [Графики]` | `[Добавить] [Заменить]` | `[Очистить]`.

### 4.3. Метрики

12 полей на синтезе рядом с ПФ — «второй экран» в миниатюре.

Лучше:

- **3–4 ключевых** всегда (например tр, σ, hуст, ζ — по приоритету задачи).
- Остальное — «Подробнее…» / раскрывающийся блок.
- Или **столбец справа от графиков** фиксированной ширины ~180–220 px (классика
  лабораторных/SCADA-экранов).

### 4.4. Идентификация

Сейчас смешаны метод, файл, кнопки, ПФ, метрики, графики.

Разнести:

- **Слева узкая панель** (~280 px): метод, файл, настройки ID, «▶ Считать».
- **Справа**: формула + графики.

Ввод (файл/метод) не конкурирует с «моделью».

### 4.5. Синтез + РКЧХ

Не добавлять отдельную вкладку «ещё одно всё».  
Внутри **Синтеза** — подрежимы:

`Вручную | Авто | РКЧХ` (`QButtonGroup` / segmented control).

Один объект (контур), разные способы настройки.

### 4.6. Связь вкладок

Copy/paste ПФ — технично, но UX слабый.

Сильнее:

- кнопки **«Передать в анализ» / «Передать в синтез»**;
- или общий **«Текущий объект»** в статус-баре:  
  `ОУ: W(p)=… · источник: идентификация`.

Все вкладки читают один session-state (`PlantModel` / документ сессии).  
Это превращает набор утилит в **продукт**.

## 5. Типографика и плотность (без смены цветовой темы)

1. Базовый UI: **10–11 pt**; формула: **14–16 pt**, не 24.
2. Вертикальный ритм: **8 / 12 / 16 px** между блоками.
3. Выравнивание: левый край модели = левый край графиков (одна сетка).
4. Пустое место — margin карточки, не случайный spacer.
5. Пустые состояния: «Задайте ПФ», «Нет кривых» — не только пустые оси.

Ориентир по площади: **графики ≈ 55–65%** высоты рабочей области.

## 6. Ориентиры (по духу, не копируя UI)

| Система | Что взять |
|---------|-----------|
| MATLAB PID Tuner / Control System Designer | Плант отдельно, регулятор, графики — холст |
| SciLab / Xcos, Octave | Компактный ввод модели, результаты крупно |
| LabVIEW / SCADA | Карточки, статус, «приборная» иерархия |
| Научные дашборды | График доминирует, контролы — 30% |

Не ориентироваться на consumer-UI (Notion, Figma) — другая задача. Ближе **scientific desktop**.

---

## 7. Принципы «как делать формы»

1. **Один фокус** на экране — либо правка модели, либо чтение результата.
2. **Формула — для чтения; поля — для правки** (не всегда одновременно).
3. **Группы в карточках**, а не виджеты «в ряд на весь QHBoxLayout».
4. **Графики** — основной холст по площади.
5. **Действия** — одна предсказуемая полоса.
6. **Сквозной объект** (ОУ/контур) между вкладками.
7. **Progressive disclosure** — сложное по запросу, не всегда на экране.

## 8. Roadmap UI (после закрытия базовой математики)

Когда математика базы (в т.ч. РКЧХ) закончена, UI лучше трогать **слоями**:

| Этап | Суть | Эффект | Ломает ввод ПФ? |
|------|------|--------|------------------|
| **1. Каркас** | Единый layout: карточка модели / toolbar / графики+метрики | Сразу «приятнее» | Нет |
| **2. Метрики** | 3–4 ключевых + «ещё» | Разгрузка верха | Нет |
| **3. ПФ** | Preview-формула + компактный edit | Главная боль формы | Частично |
| **4. Действия** | Текст на primary, группы | Понятнее | Нет |
| **5. Сессия** | Общий plant между вкладками | Ощущение продукта | Нет |

Этапы 1–2 можно сделать **без переписывания** текущего `TranFuncForm`.

## 9. Связь с текущей структурой кода

| Область | Файлы / места |
|---------|----------------|
| Вкладки | `ui/tabs/*`, `code/tabs/*` |
| Форма ПФ | `code/widgets/tf-form/*` |
| Отображение ПФ | `code/widgets/tf-display-widget.*` |
| Метрики | `code/widgets/regulation-widget.*` |
| Графики | `code/charts/*`, `code/charts/utils/*`, `code/dialogs/chart-viewer/*` |
| Стили | `data/styles/app.qss` |

При рефакторинге layout имеет смысл вынести **общий каркас вкладки** (helper / base
widget), чтобы Анализ / Синтез / Идентификация не дублировали setup.

---

## 10. Итог

Irbis уже ценен **функциональной полнотой**. Следующий уровень «приятности» —
не новые цвета, а:

- явная сцена **модель → действие → результат**;
- спокойная **карточка ПФ** (чтение vs правка);
- **метрики у графиков**, а не у формулы;
- **сквозной объект** между вкладками.

Первый практический шаг: **переразметка вкладок** (этапы 1–2). Второй — **режим
формула/редактор** для ПФ (этап 3).
